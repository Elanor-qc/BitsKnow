# SPEC-05: 卡片沉淀与上下文组装

## 目标
核心机制：AI 内嵌 JSON 沉淀 + 上下文注入。这是产品灵魂 spec。

## 内嵌协议
System prompt 约定：AI 认为本轮形成了值得沉淀的知识点时，在回复**最末尾**输出：

````
```xizhi
{"summary": "本次新增的进度摘要增量(可选)",
 "cards": [{"type": "term", "title": "VAE", "body": "变分自编码器，...(Markdown)"}],
 "notes": ["用户已理解 KL 散度的直觉解释"]}
```
````

- 无可沉淀内容时省略整个代码块
- App 侧：流式完成后解析末尾 ```xizhi 块 → 剥离后入库正文、卡片入库、notes 入 LearningNote、summary 合并入 Module.summary（合并策略：直接追加 + 截断到 800 字头部，AI prompt 要求增量式改写）
- 解析失败：正文原样保留显示（含代码块），不崩、不丢

## System prompt（模块教学）
- 角色：碎片化场景的私教；短回复优先（移动端），一次聚焦一个点
- ZPD：根据 notes 与摘要判断已掌握内容，不重教
- 沉淀时机：完整概念讲清/术语定义/纠错时才输出 xizhi 块，不要每条都输出
- 术语卡片一经沉淀要复用一致定义

## 上下文组装（每次请求）
messages = [system(教学 prompt + 模块标题 + 进度摘要 + 学习记录列表 + 术语表)] + 最近 N=20 条消息（不含 system）

## 验收
- 解析器单测：正常块、无块、畸形 JSON、多个代码块（只取最后一个 xizhi 块）、空 cards
- 模拟器端到端：一轮教学对话后复盘区出现卡片、摘要与术语表更新
